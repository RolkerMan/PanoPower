# 安卓 WebView 下网页截图与图片显示方案总结

## 现象与问题

- 在安卓应用 WebView 中，img 标签的 src 如果为本地文件（如 file:// 或 ./piggy.jpg），使用网页截图（如 dom-to-image、modern-screenshot 等）时，无法正确显示该图片，截图结果中图片为透明或丢失。
- 如果将 img src 设置为 base64（data:image/png;base64,...），网页截图方案可以正常显示图片。
- 若采用安卓原生 WebView.draw(canvas) 截图，img src 为 base64 的图片反而可能无法被截图（部分 WebView 实现或硬件加速下），但本地文件图片可被捕获。

## 结论与推荐方案

- **推荐使用网页截图方案（如 dom-to-image、modern-screenshot），并将 img src 设置为 base64 格式。**
  - 这种方式兼容性好，无需安卓 app 额外权限。
  - 适合大多数二维码、头像、装饰图片等场景。
- 如果后续图片数量较多、体积较大，或需动态管理图片资源，可再考虑：
  - 图片资源统一转 base64 并按需加载
  - 优化网页截图设置：安卓 app 设置权限，允许在网页截图时访问指定范围内的本地文件（例如截图会用到的图片目录）
  - 优化安卓原生截图方案，确保 base64 图片能被正确捕获（如关闭硬件加速等），或者让二维码图片使用本地文件路径，而不是 base64。

## 代码建议

- 将本地图片（如 piggy.jpg）转为 base64 字符串，直接作为 img 标签的 src。
- 示例：
  ```html
  <img src="data:image/png;base64,iVBORw0KGgo..." />
  ```
- 这样网页截图时能保证图片内容被捕获。

## 其他说明

- 安卓原生截图方案（WebView.draw）与网页截图方案在图片渲染机制上有差异，需根据实际需求选择。
- 若需管理大量图片资源，可结合图片管理后台、CDN 或本地缓存机制。
